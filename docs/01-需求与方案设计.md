## 1. 产品定义

一个常驻 Windows 桌面的轻量薪资小组件：按当前时间实时展示今天已经赚到的工资、距离下班还有多久，以及今日工作进度；所有薪资与作息参数可在设置页修改。

产品一句话：

> **按分钟累计今天的收入，按秒倒数下班时间；一眼看清，不打扰工作。**

本工具是**估算展示工具**，不是薪资核算或财务系统。金额按输入参数推算，不处理个税、社保、考勤异常、请假、加班费和实际发薪规则。

## 2. 已确认的需求基线

### 2.1 基础参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 月薪 | ¥33,500.00 | 计价基数 |
| 月计薪天数 | 21.75 天 | 平均模式：日薪 = 月薪 ÷ 21.75；实际工作日模式改按当月天数 |
| 上班时间 | 09:30 | 以最终确认的口径为准（初始需求写 9:00，后明确为 9 点半） |
| 午休开始 | 12:30 | 午休不计薪 |
| 午休结束 | 14:00 | 下午 14:00 开始工作 |
| 下班时间 | 19:00 | 主倒计时终点 |
| 有效工时 | 8 小时（480 分钟） | 09:30–12:30（180 分钟）+ 14:00–19:00（300 分钟） |
| 周末/节假日 | 平均模式仅周六、周日不计薪 | 实际工作日模式按 2026—2027 年国务院节假日与调休表判断 |

> 关键口径已澄清：午休为 **12:30–14:00**，因此上午 3 小时、下午 5 小时，合计正好 8 小时。

### 2.2 功能清单

1. 按分钟计算当天工资，工资数值在每个完整计薪分钟结束时更新。
2. 首页主倒计时指向当天 19:00，**午休期间倒计时继续走**。
3. 同时显示“剩余有效工时”，午休期间该数值暂停减少。
4. 周六、周日显示休息状态，今日收入为 ¥0.00。
5. 完整仪表盘：今日已赚、下班倒计时、今日进度、日薪/时薪/分钟薪、当前状态。
6. 设置页可修改月薪、月计薪天数、上下班时间、午休起止时间、窗口置顶，并切换“按当月实际工作日计薪”；默认值即上表。
7. 窗口可置顶，置顶状态可切换并记住。
8. 设置页新增“按当月实际工作日计薪”开关；开启后按当月实际工作日计算日薪，识别 2026—2027 年法定节假日和调休上班日。
9. 交付一个可在 Windows 直接运行的单文件 exe；先交付设计文档与测试用例，确认后才进入实现。

### 2.3 设计采用的补充决定（已确认）

| 决策 | 方案 |
|---|---|
| 置顶默认状态 | 默认**开启**，主界面图钉按钮可切换，设置页也有开关 |
| “设置页面”形态 | 独立设置窗口，视觉与主窗口一致；主窗口保持紧凑 |
| 无午休/多段休息 | v1 不支持；要求存在一段午休，且时间顺序合法 |
| 跨天班次 | v1 不支持，上下班必须在同一天内 |
| 节假日 | 默认平均模式仅按星期判断；可开启实际工作日模式，使用内置 2026—2027 年节假日/调休表 |
| 本月累计 | v1 不显示；只显示“今日已赚” |
| 关闭行为 | 关闭按钮直接退出，不驻留托盘，不自动开机启动 |
| 数据存储 | 默认本机 `%APPDATA%\SalaryMonitor\settings.json`；AppData 不可写时回退到 exe 同目录 `SalaryMonitor.settings.json`，不联网 |
| 界面主题 | 仅深色玻璃卡片风格 + 青蓝渐变 |
| 运行平台 | Windows 10/11 x64；当前机器验证环境为 Windows 11 |
| 主倒计时边界 | 上班前显示“距上班”倒计时；上班后切换为“距下班”；下班后显示已结束 |

## 4. 核心计算设计

### 4.1 术语

| 名称 | 含义 |
|---|---|
| S | 月薪 |
| D | 月计薪天数 |
| 日薪 | 默认工作日可获得的全天工资 |
| M | 每日有效计薪分钟数 |
| W | 当天截至当前已经完成的完整计薪分钟数 |
| 今日已赚 | 按 W 计算的当日累计工资 |
| 距下班 | 当前墙钟时间至当天 19:00 的差，包含午休时间 |
| 剩余有效工时 | M − W，午休期间不减少 |

### 4.2 公式

```text
日薪        = S ÷ D
M           = (午休开始 − 上班时间) + (下班时间 − 午休结束)
分钟薪      = 日薪 ÷ M
时薪        = 分钟薪 × 60
今日已赚    = 日薪 × W ÷ M        （0 ≤ W ≤ M）
今日进度    = W ÷ M × 100%
剩余有效分钟 = M − W
```

- 默认数据：`M = 180 + 300 = 480` 分钟，即 8 小时。
- 默认日薪：`33,500 ÷ 21.75 = 1,540.229885… → ¥1,540.23`。
- 默认分钟薪：`1,540.229885… ÷ 480 = 3.2088122… → ¥3.21`。
- 默认时薪：`3.2088122… × 60 = 192.528735… → ¥192.53`。
- 以上结果均为显示值（保留 2 位小数）；**内部计算保留 decimal 全精度，不用已四舍五入的值继续参与计算**。
- 显示采用“四舍五入（远离零）”，即 `MidpointRounding.AwayFromZero`；到下班时今日已赚严格显示为日薪的 2 位小数金额。
- 工资按“完整计薪分钟”递增：09:30:59 仍为 ¥0.00，09:31:00 变为 ¥3.21。设置页保存后立即按新参数重算当天金额。

### 4.3 实际工作日模式

开启设置页的“按当月实际工作日计薪”后：

```text
当月实际工作日 = 当月周一至周五
                 − 法定节假日落在工作日的天数
                 + 国务院安排的周末调休上班日
日薪           = 月薪 ÷ 当月实际工作日
分钟薪         = 日薪 ÷ 480
今日已赚       = 0（法定节假日/周末）
               = 日薪 × 已完成整分钟 ÷ 480（工作日/调休上班日）
```

示例：

```text
2026 年 11 月：21 个工作日 → 日薪 ¥1,595.24，分钟薪 ¥3.32
2026 年 10 月：18 个工作日 → 日薪 ¥1,861.11
2027 年 2 月： 15 个工作日 → 日薪 ¥2,233.33
```

- 法定节假日当天显示“节假日休息”，今日已赚 ¥0.00。
- 调休上班日按正常工作日计薪。
- 2028 年及以后暂无内置官方表，回退为周一至周五，并在主界面底部提示“未收录该年节假日”。
- 完整日历见 [2026—2027 日历与工作日](android/04-2026-2027日历与工作日.md)。

### 4.5 状态机

| 状态 | 判定区间 | 主界面提示 | 金额 |
|---|---|---|---|
| 休息日（周末） | 平均模式周六、周日全天；实际模式普通周末 | 周末休息 · 今日不计薪 | ¥0.00 |
| 休息日（法定节假日） | 实际模式法定节假日全天 | 节假日休息 · 今日不计薪 | ¥0.00 |
| 未上班 | 工作日 `[00:00, 09:30)` | 距上班倒计时 | ¥0.00 |
| 上午工作中 | `[09:30, 12:30)` | 上午工作中 | 按已完成分钟累计 |
| 午休中 | `[12:30, 14:00)` | 午休中 · 14:00 继续 | 冻结在 3 小时对应的金额 |
| 下午工作中 | `[14:00, 19:00)` | 下午工作中 | 按已完成分钟累计 |
| 今日已下班 | 工作日 `[19:00, 次日 00:00)` | 今日已下班 | 锁定为全天日薪 |

区间左闭右开；到达边界立刻切换状态。平均模式按本机系统时间的星期判断；实际模式另按内置节假日/调休表判断。调休上班日按工作日状态显示，主界面底部提示“今日调休上班”。午休在倒计时中视为“仍需待在公司的墙钟时间”，但不再累计工资。

### 4.6 时间与刷新

- 数据源：本机系统本地时间，不依赖网络。
- 主倒计时与当前时间：每秒刷新一次。
- 工资：仅当完整计薪分钟新增时变化，严格符合“每分钟更新”。
- 系统休眠、唤醒或手动改时间后，下一次刷新直接按当前系统时间重算，不做累加，因此不会出现漂移或多算。
- 跨过午夜后自动按新的一天重新判定；若进入周末，立即转为休息状态。

### 4.7 设置变更语义

设置保存成功后，今日已赚、进度、倒计时和费率立即按新参数重新计算。若新排班导致当前时刻处于午休或非工作区间，按新排班对应状态展示；不补偿操作前的差额。

## 5. 界面与交互设计

### 5.1 视觉方向

- 深色桌面卡片，藏蓝黑底 + 青绿到靛蓝的渐变强调。
- 圆角 26px、细描边、柔和外阴影、局部光晕，营造克制的玻璃质感；不承诺真实桌面背景模糊。
- 大数字突出“今日已赚”和“距离下班”，小字号承载费率、日期和解释信息。
- 主窗口固定为紧凑尺寸 **504 × 524 DIP**，不提供缩放；设置窗口 **604 × 700 DIP**，过小屏幕时内容可滚动。

### 5.3 主窗口交互

| 区域 | 交互 |
|---|---|
| 标题栏空白区 | 按住拖动窗口 |
| 图钉按钮 | 切换置顶；激活态高亮；Tooltip 提示“保持置顶/取消置顶” |
| 设置按钮 | 打开模态设置窗口 |
| 最小化按钮 | 最小化到任务栏 |
| 关闭按钮 | 退出整个应用；不驻留托盘 |
| 主界面 | 无其他可点击区域，避免误触 |

- 应用不出现在系统托盘，不自动启动。
- 无边框窗口的支持区域包括圆角外轮廓、拖拽、最小化、关闭和键盘焦点。

#### 字段与校验

| 字段 | 默认值 | 输入格式 | 校验规则 |
|---|---|---|---|
| 月薪 | 33500.00 | 数字，可带千分位和两位小数 | 必填；`> 0`；上限 9,999,999.99 |
| 月计薪天数 | 21.75 | 数字，最多 2 位小数 | 平均模式必填；`> 0` 且 `≤ 31`；实际模式隐藏并保留原值 |
| 按当月实际工作日计薪 | 关 | 开关 | 开启后按 2026—2027 年日历计算；其他年份回退周一至周五 |
| 上班时间 | 09:30 | `H:mm` 或 `HH:mm` | 合法 24 小时制时间，统一格式化为 `HH:mm` |
| 午休开始 | 12:30 | 同上 | 必须晚于上班时间 |
| 午休结束 | 14:00 | 同上 | 必须晚于午休开始 |
| 下班时间 | 19:00 | 同上 | 必须晚于午休结束 |
| 窗口置顶 | 开 | 开关 | 无 |

同时满足：`上班时间 < 午休开始 < 午休结束 < 下班时间`，且为同一天内的班次。有效工时由四个时间自动计算，**不单独输入**，避免与时间段冲突。

保存行为：

1. 点击保存后先做完整校验。
2. 校验失败：在对应字段下方显示中文错误提示，字段边框高亮；不关闭设置窗口、不写入配置。
3. 校验成功：写入配置文件，刷新主界面，关闭设置窗口。
4. 写盘失败：在设置窗口底部显示错误提示，保留用户输入，不应用未保存的设置。
5. 取消、关闭设置窗口或按 Esc：放弃未保存的修改。
6. 恢复默认值：只把表单恢复为默认值，仍需点击“保存设置”才应用；可取消。

## 6. 技术方案

### 6.1 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 平台 | Windows 10/11 x64 | 目标场景明确 |
| UI | WPF（.NET Framework 4.8） | 当前环境已具备 WPF 运行库与 C# 编译器；可做自绘深色界面 |
| 语言 | C#（C# 5 语法，兼容系统自带编译器） | 环境无 .NET SDK / Node，无需联网安装工具链 |
| 界面实现 | 纯 C# 代码构建控件，不使用 XAML | 用系统自带 `csc.exe` 即可编译，避免安装 MSBuild/WPF 构建链 |

| 配置 | JSON（`DataContractJsonSerializer`） | 系统内置，格式可读，便于排错 |

- Windows 11（10.0.26200），x64。
- .NET Framework 4.8（Release 533509）。
- C# 编译器 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（C# 5）。
- WPF 程序集与 GAC 构建任务存在。
- 无 .NET SDK、无 Node.js、无可用外网下载条件；方案不依赖它们。

> 运行 exe 的机器需要具备 .NET Framework 4.8（Windows 10/11 通常已内置）。exe 不包含也不会自动安装 .NET Framework。

### 6.3 关键设计

- **纯计算核心**：`PayCalculator` 输入“参数 + 当前时间”，输出不可变的展示快照。UI 只负责渲染；方便用固定时间做边界测试。
- **可注入时钟**：核心计算接收 `DateTime now`。UI 正式版使用系统时间。测试构建可通过测试入口注入固定时间，**交付版不提供改时间入口**。
- **单一刷新循环**：主窗口每 1 秒刷新一次；同一份快照同时驱动状态、倒计时、金额、进度和进度条，避免各控件数值不一致。
- **配置回退**：文件不存在、JSON 损坏、字段非法时退回全部默认参数，应用仍可启动；v1 配置可迁移到 v2。
- **日历数据**：`WorkdayCalendar` 内置 2026—2027 年法定节假日和调休日，按当月实际工作日计算；其他年份回退为周一至周五。
- **原子写入**：正常情况下先写临时文件，再替换正式文件；若受限权限环境拒绝替换，则自动降级为覆盖写入，保证设置仍可保存。
- **可写路径探测**：启动时分别探测 AppData 与 exe 同目录；AppData 不可写时自动使用 exe 同目录的 `SalaryMonitor.settings.json`，并将已有 AppData 配置迁移过去，避免受限启动器下出现“访问被拒绝”。
- **单文件**：不使用外部图片/字体/动态库，图标与 manifest 作为资源嵌入 exe。
- **DPI**：manifest 声明 Per-Monitor V2；布局使用 WPF 的 DIP，适配 100%/125%/150% 缩放。
- **无提权**：普通用户权限运行；优先写用户 AppData，AppData 不可写时回退到 exe 同目录；不请求管理员权限。

### 6.4 配置文件

```json
{
  "version": 2,
  "monthlySalary": 33500,
  "monthlyWorkDays": 21.75,
  "workStartMinutes": 570,
  "lunchStartMinutes": 750,
  "lunchEndMinutes": 840,
  "workEndMinutes": 1140,
  "alwaysOnTop": true,
  "actualWorkdaysEnabled": false
}
```

- 默认路径：`%APPDATA%\SalaryMonitor\settings.json`。
- 受限启动回退：若 AppData 目录不可写，则在 exe 同目录使用 `SalaryMonitor.settings.json`；首次回退时自动复制原 AppData 配置，后续启动优先读取已存在的便携配置。
- v1 配置（无 `actualWorkdaysEnabled`）会按 `false` 迁移到 v2，保留原月薪、天数、时间和置顶状态；v2 才写入新字段。
- 时间以“当天 0 点起的分钟数”保存，避免时区/日期格式差异；UI 始终编辑和显示 `HH:mm`。
- 保存成功才更新内存中的运行参数。
- 配置文件不对用户暴露编辑入口，但格式保持可读，便于排错。

### 6.5 异常与边界策略

| 情况 | 行为 |
|---|---|
| 配置缺失/损坏 | 使用默认值启动，不弹阻断式错误框 |
| 系统睡眠后唤醒 | 下一次 tick 按当前时间重算 |
| 跨过午夜 | 重新判断星期和新一天，必要时清零或进入休息日 |
| 倒数到 0 | 主计时显示 00:00:00，状态切到已下班，金额满额 |
| 用户修改排班后当前时间不再处于工作段 | 立即冻结或归零至对应状态，不补发差额 |
| 设置写盘失败 | 保留设置窗口，显示错误，不应用修改 |
| AppData 不可写 | 自动回退到 exe 同目录 `SalaryMonitor.settings.json` 并保存；两者都不可写时显示明确错误 |
| 屏幕过小/缩放过大 | 主窗口按工作区收缩；设置窗口限制在工作区内并支持滚动 |
| 应用失去焦点 | 继续后台刷新，不抢焦点，不弹通知 |

### 6.6 构建与交付流程

1. 编写核心计算 + 自动化测试，先让全部计算/校验/持久化用例通过。
2. 实现主窗口和设置窗口。
3. 使用测试构建在固定时间下核对各状态与视觉。
4. 编译正式单文件 exe，嵌入图标与 manifest。
5. 启动正式 exe 做冒烟测试，检查无控制台、置顶、设置持久化、退出。
6. 输出 `dist\薪资显示器.exe`、README 和最终测试记录。

构建命令会在 `build.ps1` 中固化，不依赖网络或包管理器。

## 8. 风险与限制

| 风险/限制 | 影响 | 应对 |
|---|---|---|
| 应用未数字签名 | 首次运行可能被 SmartScreen 提示 | README 说明；正式分发需代码签名，v1 不包含 |
| 依赖系统 .NET Framework 4.8 | 极旧/精简 Windows 可能无法启动 | 明确运行要求；交付前在当前 Windows 11 验证 |

| 金额四舍五入 | 显示值可能每分钟增加 ¥3.20/¥3.21 交替 | 内部全精度、仅显示两位；符合常规货币展示 |

| 自绘无边框窗口 | 不同 Windows 版本可能有细微差异 | 优先兼容 Windows 10/11，做 DPI 与多版本视觉验证 |

## 10. 已确认的设计决定

以下内容已于 2026-11-05 经确认并进入实现；v1.1.0 追加实际工作日模式：

1. **排班口径**：09:30–12:30、午休 12:30–14:00、14:00–19:00，有效 8 小时。
2. **工资更新**：只按完整计薪分钟递增（09:31 才显示第一分钟工资），倒计时按秒刷新。
3. **默认置顶开启**，可在主界面和设置页切换。
4. **默认周末规则**：平均模式仅按周六/周日判断；可开启实际工作日模式，应用 2026—2027 年法定节假日与调休表。
5. **设置页为独立窗口**，所有参数保存后立即生效并重算今日工资。
6. **交付为单文件便携 exe**，需系统具备 .NET Framework 4.8，不做安装包与数字签名。
7. **视觉方向**：深色玻璃卡片 + 青蓝渐变，采用概念稿的布局和信息层级。

实现结果与验收证据见 [`03-测试记录.md`](03-测试记录.md)。
