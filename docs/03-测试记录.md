### 测试中发现并修复的问题

在 UI 自动化执行“第二次保存”时发现：受限权限环境中 `File.Replace` 可能抛出“访问被拒绝”，原有代码未处理该异常，导致设置无法再次保存。

修复：在 `SettingsStore` 中捕获 `UnauthorizedAccessException` 并降级为覆盖写入；新增回归用例 **STORE-010**，验证连续两次保存后配置正确更新。

用户随后反馈：普通启动修改设置时仍提示“保存设置失败：对路径……访问被拒绝”，以管理员身份启动则可保存。复现确认：该实例由受限启动器拉起，进程完整性级别为 **Low（S-1-16-4096）**；Windows 的强制完整性策略拒绝低完整性进程写入 `%APPDATA%` 和 `LocalLow`，而提权后的高完整性进程可以写入。这不是配置文件 ACL 损坏，重新双击 exe 可以规避，但仅靠提示无法让受限启动方式保存。

修复：新增 `SettingsPathResolver`，启动时用临时探针分别检测 AppData 与 exe 同目录；AppData 不可写时自动迁移并使用 exe 同目录的 `SalaryMonitor.settings.json`，不请求管理员权限。新增 **STORE-011～STORE-016** 覆盖路径选择、迁移、双只读读取和迁移失败保护。修复后回归测试通过；当前自动化测试总计 **74/74**；另以正式 exe 的隔离副本在 Low Integrity 下完成真实 UI 保存与重启验证（见 4.1）。

另反馈下班后状态文字“今日已下班”显示不全。原状态胶囊使用固定 `Height = 24`，状态列又优先让日期/时间占用宽度；这两个约束在字体行高较大、系统文字缩放或窄窗口下都可能挤压文字。修复：

- 状态胶囊改为 `MinHeight = 24`，上下各留 4 DIP 内边距，高度随字体自动增长；右侧内边距增至 12 DIP，状态文字自身再留 1 DIP，避免字形右边缘被裁切。
- 状态栏第一列改为 `Auto`，日期/时间列改为 `Star` 并右对齐；空间不足时优先保证状态文字完整。
- 以 125% 缩放、504 DIP 和 460 DIP 窄窗重新截图核对，“今日已下班”均完整；设置页与新增实际模式截图已用 v1.1.0 UI 生成，旧五态截图保留 v1.0.2 版本。

## 6. 构建稳定性

- 构建可重复执行，`dist` 与 `build` 会被覆盖更新。
- 构建脚本在编译失败或自动测试失败时返回非零退出码，不会交付旧测试通过的新包。
- `build.ps1` 同时生成 UI 测试构建，但 **dist 只包含正式 exe**；运行时若 AppData 不可写，会在 exe 同目录生成便携配置。
- 正式版不包含测试时钟、截图和配置路径覆盖入口。
